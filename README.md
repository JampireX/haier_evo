# Haier Evo integration
[![hacs_badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/custom-components/hacs) [![stability-beta](https://img.shields.io/badge/stability-beta-33bbff.svg)](https://github.com/mkenney/software-guides/blob/master/STABILITY-BADGES.md#beta)

Неофициальная интеграция для работы [Haier Evo](https://haieronline.ru/evo-iot/) (RU, KZ, BY).

Бета-версия: может работать некорректно.

## Отличия от оригинала

Это форк [and7ey/haier_evo](https://github.com/and7ey/haier_evo) от его версии 0.3.15 (15.05.2026). На октябрь 2026 года оригинал с тех пор не обновлялся; здесь вышли версии 0.3.16 – 0.3.26-beta.21.

**Исправлено**
- Потеря команд. Перед отправкой проверяется соединение, после отправки — что сокет не закрылся. Если облако не ответило на команду за 10 с, она отправляется ещё раз в новой WebSocket-сессии. Если нет ответа и на повтор, в логе появляется ошибка `CMD LOST`, а HA показывает реальное состояние устройства. Отказ устройства (`errNo ≠ 0`) тоже возвращает реальное состояние.
- Зависшие обновления. WebSocket-сессия, по которой долго ничего не приходит, переподключается. Состояние устройств раз в 5 минут перечитывается по REST, но не откатывает только что отправленную команду.
- WebSocket:
  - переподключение больше не обнуляет новый сокет: из-за этого поток мог крутиться без связи до 30 минут;
  - ошибки соединения и исключения при разборе сообщений пишутся в лог (раньше терялись);
  - при повторяющихся сбоях пауза между попытками растёт до 5 минут, а не 5 секунд бесконечно;
  - сессия, по которой облако за минуту ничего не прислало, пересоздаётся: пауза между попытками растёт до 5 минут, вторая попытка идёт с обновлённым токеном, команда прерывает паузу. Первая такая сессия отмечается в логе предупреждением.
- Токен, который сервер отклонил раньше срока (HTTP 401 или закрытие WebSocket с кодом 1007), обновляется сразу. В оригинале интеграция не работала до локального истечения токена.
- Ошибки при запуске. При неверном пароле HA открывает повторную авторизацию, при сбое сети, 429 или 5xx сам повторяет настройку. В оригинале запись оставалась в ошибке настройки, и HA её не повторял. Устройство, которое не ответило при запуске, подключается позже.
- Токены хранятся отдельно для каждой записи интеграции и привязаны к почте и региону. Несколько аккаунтов работают одновременно, повторно добавить тот же аккаунт нельзя, логин и пароль проверяются при добавлении и изменении.
- Описания моделей: нетронутые копии в `/config/haier_evo.<модель>.yaml` обновляются из пакета (в оригинале копия навсегда закрывала исправления), отредактированные используются как раньше. Описание Casarte CASWD129C1CU раньше не загружалось из-за длины имени.
- Отладочный адрес `/api/haier_evo` требует входа в HA (в оригинале открыт всем в сети); данные для отчёта об ошибке — штатная диагностика HA.
- Настройки интеграции открываются на новых версиях HA (в оригинале ошибка 500, [#96](https://github.com/and7ey/haier_evo/issues/96)).
- Кондиционер:
  - команда включения отправляется всегда (в оригинале она пропускалась, если интеграция считала кондиционер уже включённым);
  - включение не сбрасывает настройки: текущий режим заново не отправляется (в «Авто» это ставило 24° и авто-вентилятор);
  - соблюдаются правила API о том, что сейчас нельзя менять, как в приложении Evo: из выключенного состояния сначала уходит включение, а режим и температура — после подтверждения; в режиме вентиляции нет «авто»-скорости, в «Авто» и «Осушении» нет «Тихого» и «Турбо»;
  - режим, который интеграция не знает, показывается как «неизвестно», а не ломает сущность;
  - `climate.set_temperature` с `hvac_mode` включает кондиционер в нужном режиме;
  - «Тихий» и «Турбо» обновляются по данным устройства;
  - кондиционер не пищит при каждом запуске HA (оригинал после запуска отправлял ему команду температуры);
  - запоздавший статус не откатывает только что отправленную команду.
- WebSocket. Ping с таймаутом распознаёт «полуоткрытое» соединение. Убран обработчик ping с неверной сигнатурой, который падал на каждом ping сервера.
- Зависимости:
  - `tenacity` объявлена в манифесте: оригинал её использует, но не объявляет, а в Home Assistant Core её может не быть;
  - `websocket-client>=1.9.2`, потому что в 1.9.1 сломано закрытие соединения.
- Совместимость с новыми версиями HA:
  - климат использует свойства `native_*`;
  - данные записи хранятся в `entry.runtime_data`;
  - отключённые сущности не вызывают ошибок;
  - убрана константа, которую удалят в HA 2027.5.

**Добавлено**
- Стиральные машины, проверено на HW60-BP12929AE (в оригинале эта модель не добавлялась, [#92](https://github.com/and7ey/haier_evo/issues/92)). В оригинале были выбор программы, температуры и отжима из YAML модели, оставшееся время и статус. Добавлено:
  - программы берутся из облака, текущая программа определяется по устройству;
  - этап стирки;
  - удалённое управление: когда оно выключено, команды не отправляются, как в приложении;
  - значения температуры и отжима из программ устройства, например 1200 об/мин;
  - оставшееся время собирается из часов и минут (или одного атрибута), у выключенной машины показывается 0, а не последнее значение;
  - у моделей без своего YAML температура и отжим берутся из значений API.
- Карточка кондиционера `custom:haier-evo-ac-card` с визуальным редактором, подключается автоматически (см. [ниже](#карточка-кондиционера)).
- Диагностика в логе:
  - каждая команда и ответ облака: `CMD OUT`, `CMD ACK`, `CMD REJECTED errNo=…`, `CMD NO ACK`, `CMD LOST`;
  - переход устройства в OFFLINE;
  - WebSocket-сессия, по которой облако ничего не присылает.

**Сопровождение**
- Каждое изменение проверяется в GitHub Actions (валидация HACS и hassfest). Релиз создаётся автоматически по версии из `manifest.json`.
- Вопросы и ошибки этой версии — в [Issues этого репозитория](https://github.com/JampireX/haier_evo/issues).

## Поддерживаемые устройства
Ниже приведен список типов устройств, работа с которыми была **проверена пользователями**:

- Кондиционеры
- Холодильники
- Стиральные машины (HW60-BP12929AE)

В действительности интеграция должна поддерживать больше устройств. 
Если интеграция некорректно работает с вашим устройством или поддерживает не все функции - сообщите в [Issues](https://github.com/JampireX/haier_evo/issues) об этом. 

## Совместимость
Haier предлагает разные мобильные приложения для разных рынков и стран. Некоторые устройства совместимы с более чем одним приложением. Эта интеграция поддерживает только устройства, которыми можно управлять через приложение [Evo](https://haieronline.ru/evo-iot/). Загрузите приложение Evo и проверьте совместимость с вашим устройством.

## Установка

### 1. Установка HACS (если не установлен)
Для работы интеграции требуется наличие HACS.
Инструкция для установки https://www.hacs.xyz/docs/use/download/download/

### 2. Добавление репозитория Haier Evo

Так как интеграция является кастомной, её необходимо добавить в HACS как пользовательский репозиторий:

1. Откройте **HACS** в боковой панели Home Assistant.
2. Нажмите на три точки (⋮) в верхнем правом углу и выберите **Custom repositories** (Пользовательские репозитории).
3. В поле **Repository** вставьте ссылку: `https://github.com/JampireX/haier_evo`
4. В поле **Category** выберите **Integration** (Интеграция).
5. Нажмите **Add** (Добавить).
6. Теперь найдите **Haier Evo** в поиске HACS и нажмите **Download** (Загрузить).

### 3. Настройка

1. Перезапустите Home Assistant.
2. Перейдите в **Настройки** > **Устройства и службы** > **Добавить интеграцию**.
3. Найдите в списке **Haier Evo** и введите данные вашего аккаунта от приложения Evo.

## Диагностика

Данные для сообщения об ошибке: **Настройки** → **Устройства и службы** → **Haier Evo** → **⋮** → **Скачать диагностику**. В файле — ответы облака по каждому устройству и то, как интеграция их разобрала; почта, пароль, токены и серийные номера в нём скрыты.

Отладочный адрес `/api/haier_evo` требует входа в Home Assistant (долгосрочный токен из профиля): `curl -H "Authorization: Bearer <токен>" http://<адрес HA>:8123/api/haier_evo`. Включается и выключается переключателями «Haier Evo HTTP GET/POST».

## Карточка кондиционера

Интеграция сама подключает карточку `custom:haier-evo-ac-card` — ресурс добавлять не нужно. Её можно выбрать в редакторе панели (основные настройки есть в визуальном редакторе, всё остальное — в YAML). Очищенное в редакторе поле возвращает значение по умолчанию.

По умолчанию карточка минималистична: название и температура в комнате, кнопка питания, целевая температура, иконки режимов, одна строка компактных списков (вентилятор, жалюзи, пресет) и иконки функций устройства. Подписи значений берутся из переводов Home Assistant.

```yaml
type: custom:haier-evo-ac-card
entity: climate.kondicioner          # единственный обязательный параметр
```

Все параметры:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `name` | имя сущности | Своё название |
| `show_name`, `show_current`, `show_power` | `true` | Название, температура в комнате, кнопка питания |
| `show_labels` | `false` | Подписи под иконками и в списках (иначе — только подсказки) |
| `compact` | `false` | Уменьшенные отступы и кнопки |
| `hide_when_off` | `false` | `true` — у выключенного (или недоступного) кондиционера оставить только заголовок и режимы; или список секций, которые скрывать (список задаётся только в YAML, визуальный редактор показывает его без изменения) |
| `sections` | `[temperature, modes, fan, swing, swing_horizontal, preset, switches]` | Какие секции показывать и в каком порядке; доступны ещё `selects` и `sensors` |
| `control_style` | `pills` | `pills` — компактные списки в одну строку, `chips` — ряд кнопок на каждый параметр |
| `modes`, `fan_modes`, `swing_modes`, `swing_horizontal_modes`, `preset_modes` | все доступные | Какие значения показывать и в каком порядке. Пока `modes` не задан, режим «Выкл» не показывается, если включена кнопка питания (`show_power`) |
| `switches`, `selects`, `sensors` | всё с устройства | Явный список сущностей (можно чужие: `input_boolean`, `light`, `input_select`, …) |
| `exclude` | — | Сущности, которые не показывать |
| `temperature_step` | шаг сущности | Шаг кнопок −/+ |
| `debounce` | `700` | Через сколько мс после последнего нажатия −/+ отправить температуру (несколько нажатий — одна команда) |
| `labels` | — | Свои подписи: `{mode: {cool: Холод}, fan: {auto: Сам}}` |
| `icons` | — | Свои иконки: по режиму (`cool`, `heat`, …), элементу управления (`fan`, `swing`, `swing_horizontal`, `preset`), кнопке (`power`, `increase`, `decrease`), значку комнатной температуры (`current_temperature`) или сущности: `{cool: mdi:snowflake-variant, fan: mdi:fan, power: mdi:power-standby, switch.x: mdi:lamp}` |
| `colors` | цвета темы | Цвета режимов: `{cool: '#03a9f4'}` |
| `accent_color` | цвет темы | Цвет активных кнопок |
| `style` | — | Дополнительный CSS; размеры задаются переменными `--hac-btn`, `--hac-temp-size`, `--hac-gap`, `--hac-radius`, `--hac-accent` |

Пример:

```yaml
type: custom:haier-evo-ac-card
entity: climate.kondicioner
name: Спальня
compact: true
hide_when_off: true
sections: [temperature, modes, fan, swing, switches]
modes: [cool, heat, dry, auto]
exclude: [switch.kondicioner_sound]
labels:
  mode: {cool: Холод, heat: Тепло}
```
